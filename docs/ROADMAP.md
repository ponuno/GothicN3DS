# Что дальше

## Что смотреть в эмуляторе и на консоли

Ландшафт, объекты, вода, ходьба, заделка швов, фоновая подгрузка и новый порядок кадра уже запускались на настоящих данных на New 3DS (замеры — в README). Эта версия добавляет героя: в `data.pak` появляются модель и анимации, поэтому его нужно запечь заново. После запекания стоит сверить:

| Что смотреть | Если не так |
|---|---|
| В отчёте конвертера есть блок `== model 'hero' ==` со строками `character`, `animations`, `clips` | строка `character: … not found` в отчёте первого мира скажет, какого файла не хватило; имена задаются `--hero-script`, `--hero-body`, `--hero-head` |
| Герой стоит на земле в полный рост, спиной к камере, с кожей и лицом | висит в воздухе или утонул — строка `animations: hips`; вывернут или «прозрачный» — `character mesh`; смотрит не туда — `character faces`; серый — `character skin` и `model textures not found` |
| Руки и ноги согнуты как у человека, а не скручены | строка `animations: rotations read …`: первое число должно быть намного меньше второго; чтение — `importZenActor` (`import_zen.cpp`) |
| При беге ноги не скользят по земле; при слабом наклоне Circle Pad герой идёт шагом | скорость в строке `clips` (`S_RUNL …cm/s`) и строка `hero` на нижнем экране |
| Прыжок, падение с уступа, плавание выглядят уместно: пловец лежит в воде, а не стоит в ней | какие анимации нашлись — `clips` и `animations not found`; высота пловца — `Hero::update` (`engine/hero.cpp`) |
| У стены камера приближается и не показывает мир сквозь стену | `Camera::boomRadius`, `Camera::distance` (`engine/app.h`), `App::placeCamera` |
| Кадр с героем по-прежнему 16,7 мс там, где был | герой — это несколько вызовов отрисовки (сколько именно и сколько треугольников, скажет строка `skeleton` отчёта); строки `cpu`, `gpu` |
| Мир выглядит как раньше: нет пропавших или искажённых полигонов | новый шейдер (`world.v.pica`); для сравнения запустить с зажатой R — прежний шейдер, без героя |
| Фиолетового полигона в хижине больше нет | строка `untextured` в отчёте называет материал и цвет |
| Внутри замка игра возвращается к 60 к/с, когда вид это позволяет, а на 30 к/с объекты видны на полную дальность | `PacerConfig` (`engine/pacer.h`): `probeBelow`, `probeFit`, `probeEvery` |
| Вплотную к стенам и частоколу нет светлых линий по стыкам полигонов | строка `seams` в отчёте; координаты места со строки `pos` — тот же вид открывается на ПК через `g3ds-host --cam`; допуск — `--seal` |
| При ходьбе через границы чанков нет рывков: `update … worst` меньше ~2 мс, `late` равно 0 | `loader` должен показывать `thread`; для сравнения запустить с зажатой B |
| Когда `load` подходит к 90%, `detail` опускается ниже 100% и кадр остаётся 16,7 мс; если не хватает, включаются ровные 30 к/с | пороги в `PacerConfig` (`engine/pacer.h`); для сравнения запустить с зажатой X |
| Картинка цела, программа не зависает; у ворот замка кадр 16,7 мс при `gpu` около 97% | новый порядок кадра (`frameEnd` в `gfx_c3d.cpp`); запустить с зажатой Y: прежний порядок, кадр там стоит `cpu + gpu` |
| При ходьбе и поворотах нет мелких рывков дважды в секунду | шаг игры берётся из `FrameStats::frameMs` (время между кадрами на экране) |
| На стыках чанков нет мерцающих точек, даже вплотную | расчёт позиции от камеры в `world.v.pica`; шаг решётки `positionStep` в `chunker.h` |
| Вид на Старый лагерь со спуска: программа не падает, `dropped draws` на нижнем экране равен 0, `cmdbuf` заметно меньше 100% | число вызовов (`draws`) и заполнение буфера с нижнего экрана; размер буфера — `kCommandBufferBytes` в `gfx_c3d.cpp` |
| Сундуки, кровати, двери, столы стоят на местах и собраны правильно | строка `models` в отчёте (расхождение позы покоя) и `objects by kind`; поза считается в `restPose` (`import_zen.cpp`) |
| Паутина, световые пятна и другие декали повёрнуты и растянуты правильно | `makeDecal` (`import_zen.cpp`): размер, сторона, режим смешивания |
| Вода полупрозрачная, сквозь неё видно дно, текстура движется | строка `water` в отчёте; прозрачность — `kWaterOpacity` |
| В реке и озере игрок идёт вброд, затем плывёт; под водой вид затянут мутью | параметры в `PlayerConfig` (`engine/player.h`) |
| Мелкие предметы появляются при приближении, а не висят в воздухе вдали | `detailDistance` в `StreamConfig`; пороги размера — `kSmallRadius`, `kMediumRadius` |
| Вход в Старую шахту и другие переходы переносят в нужный мир и ставят игрока на землю у входа | строка `portals` в отчёте: найдена ли точка прибытия |
| В шахте нет неба, фон тёмный, свет не меняется со временем суток | строка `indoor world` в отчёте |
| По лестницам можно подняться и спуститься | строка `ladders`; логика в `Player::climb` |
| После выхода и запуска игрок там же, где был | `state.bin` рядом с `data.pak` |

## Решение по этапу 0

Критерий из плана: Старый лагерь должен давать около 20 кадров/с с запасом по памяти. Замер на New 3DS сделан: мир с объектами идёт на 60 к/с почти везде (в среднем половина кадра у видеочипа, 18–28% у процессора), свободно 17 МБ линейной памяти. Запас есть. Мир — только часть нагрузки, поэтому до окончательного вывода нужны ещё два замера:

- загрузка `GOTHIC.DAT` в виртуальную машину Daedalus из ZenKit на консоли (время и память);
- 30–40 скелетных моделей в кадре. Одна (герой) уже есть: каждая — это выборка анимации на ~50 костей на процессоре и 4–6 вызовов отрисовки с матрицами костей.

Если мир один занимает больше половины кадра, сначала стоит попробовать пункты из раздела «Производительность».

## Ближайшие задачи

**Персонажи и игра (этапы 3–4)**

- Остальные персонажи: те же модель и анимации, расставленные по миру. Кто где стоит, задано в скриптах (`STARTUP.D`), поэтому нужна виртуальная машина Daedalus из ZenKit; до неё можно расставить персонажей по путевым точкам для замера нагрузки.
- Одежда и доспехи: другие тела `.MDM` на том же скелете и оверлеи анимаций (`HUMANS_*.MDS`).
- Слои анимации (повороты на слое 20), события анимаций (шаги, звук), переходы `T_…_2_…` между состояниями; сейчас состояния сменяются плавным смешиванием.
- Анимации лестницы, ныряния, подъёма на уступ; урон от падения.
- Предметы в мире и в руках (точки `ZS_RIGHTHAND` скелета уже в модели), взаимодействие с сундуками, кроватями, дверями.
- Диалоги, инвентарь, бой — после виртуальной машины.

**Мир (этап 2)**

- Частицы (костры, факелы, дым) и спрайты, повёрнутые к камере. Сейчас пропускаются, конвертер пишет их число.
- Двери, ворота и подъёмники (`zCMover`, `oCMobDoor`): рисуются неподвижными и без столкновений; нужны анимация и срабатывание.
- Предметы, лежащие в мире (`oCItem`): их вид задан в скриптах, поэтому они появятся вместе с виртуальной машиной Daedalus.
- Облака и светила на небе; сейчас это градиент.
- Детальные лайтмапы: сейчас свет лайтмапа берётся только в вершинах, внутри больших полигонов детали теряются.
- Зоны тумана и дальности (`zCZoneZFog`, `zCZoneVobFarPlane`): сейчас из них берётся только цвет фона подземного мира.
- Порталы и секторы BSP для помещений. Это же главный резерв скорости внутри зданий: в замке сейчас рисуется всё, что стоит за стенами (93% видеочипа и 30 к/с при 16% процессора).
- Ныряние, урон от падения, подъём на уступы.
- Отражения и волны на воде.

**Производительность**

- Упрощённые меши объектов для дальних чанков: в файлах `.MRM` есть данные прогрессивного меша (`wedge_map`), по ним можно убирать вершины.
- Кадр на консоли раньше стоил «время процессора + время видеочипа» (у citro3d один буфер команд); теперь они перекрываются, и остаётся большее из двух. Дальше видеочип разгружают меньшим числом треугольников (упрощённые меши вдали), а процессор — меньшим числом вызовов отрисовки (сейчас 430–690 на кадр, около 7 мкс каждый).
- Сброс всей линейной памяти из кэша в конце кадра (`C3D_FrameEnd(0)`) по замеру стоит меньше четверти миллисекунды; менять его не нужно.
- Фоновый поток подгрузки сейчас работает на том же ядре, что и основной, с приоритетом ниже: он занимает время, пока основной ждёт видеочип и кадровую развёртку. На New 3DS есть ещё два ядра; перенос потока туда стоит попробовать, если `job` на нижнем экране окажется велик.
- Заделка швов добавляет треугольники. Если строка `seams` покажет заметную прибавку, T-стыки дальних объектов можно не закрывать: издалека они не видны.
- Часто используемые текстуры в VRAM (6 МБ), остальные в линейной памяти.
- Объекты запекаются в чанки копиями. Если архив или память окажутся велики, повторяющиеся меши (деревья) стоит вынести в экземпляры.
- Порядок индексов под кэш вершин.
- Стереоскопический режим: второй кадр для второго глаза, когда хватит запаса по времени.

**Данные**

- Контрольные суммы ресурсов в архиве: сейчас повреждение ловится только проверкой заголовков и индексов.
- Gothic 2 и моды: ZenKit читает и их, но конвертер проверялся только на Gothic 1. Понадобятся порядок монтирования архивов `.mod` и проверка на настоящих файлах.
