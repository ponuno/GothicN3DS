# Форматы данных

Все числа little-endian. Структуры описаны в `core/include/g3ds/`, их размеры закреплены через `static_assert`. Консоль ничего не разбирает и не перекодирует: чанк и текстура копируются в память GPU как есть.

## Архив G3PK (`pak.h`)

Один файл `data.pak` на SD-карте.

```
PakHeader (32 байта)
данные ресурсов, каждый выровнен на 4 байта
PakEntry[entryCount] (по 24 байта), отсортированы по hash
таблица имён (строки с нулём на конце)
```

| Поле `PakEntry` | Смысл |
|---|---|
| `hash` | FNV-1a от имени в нижнем регистре; `\` приравнивается к `/` |
| `offset`, `packedSize` | положение и размер в файле |
| `size` | размер после распаковки |
| `type` | 0 blob, 1 текстура, 2 индекс мира, 3 чанк, 4 текст |
| `codec` | 0 без сжатия, 1 один блок LZ4 |
| `nameOffset` | имя в таблице имён, нужно только инструментам |

Ресурс ищется двоичным поиском по хешу. Конвертер отказывается писать архив при совпадении хешей. Сжатие применяется, только если экономит больше 1/16 размера.

Имена: `tex/<имя текстуры>`, `world/<мир>`, `world/<мир>/<номер чанка>`, `meta/report` (отчёт конвертера), `meta/start` (имя мира, с которого начинается игра). Имя мира — имя его файла без расширения в нижнем регистре: `WORLD.ZEN` → `world`.

## Текстура G3TX (`tex.h`)

```
TexHeader (16 байт): magic, width, height, format, mipCount, flags, dataSize
мип-уровни подряд, от большего к меньшему
```

- `format`: 0 — ETC1 (4 бита на пиксель), 1 — ETC1A4 (8 бит, альфа 4 бита).
- Размеры — степени двойки от 8 до 1024; наименьший мип-уровень имеет сторону 8.
- `flags` бит 0: текстура с вырезом, рисуется с альфа-тестом.

Данные уровня лежат в раскладке PICA200:

1. Строки хранятся снизу вверх: хранимая строка = `height − 1 − строка изображения`.
2. Изображение разбито на тайлы 8×8, тайлы идут построчно.
3. В тайле четыре блока 4×4 в Z-порядке: левый верхний, правый верхний, левый нижний, правый нижний (в хранимых координатах).
4. Блок ETC1 — стандартные 8 байт в обратном порядке.
5. В ETC1A4 перед блоком цвета идут 8 байт альфы: 16 полубайтов, тексель `(x, y)` имеет номер `x·4 + y`.

Координата `v = 0` соответствует верхней строке изображения, как в Direct3D и в данных ZenGin, поэтому текстурные координаты не пересчитываются.

## Мир G3WD и чанки G3CH (`world.h`)

В одном архиве может лежать несколько миров. Индекс мира загружается целиком и остаётся в памяти:

```
WorldHeader (96 байт)
WorldMaterial[materialCount] (по 16 байт)
u32 textureHash[textureCount]
WorldPortal[portalCount] (по 48 байт)
WorldLadder[ladderCount] (по 24 байта)
ChunkInfo[chunkCount] (по 40 байт)
```

`WorldHeader` хранит версию формата (сейчас 3), размер ячейки сетки, границы мира, число треугольников, точку старта (`spawnPos`, `spawnYaw`), размеры таблиц и флаги. Флаг `WORLDF_INDOOR` отмечает мир без неба (шахту): фон и туман берут цвет `fogColor`, время суток на свет не влияет.

`WorldMaterial`:

| Поле | Смысл |
|---|---|
| `texture` | номер в таблице текстур; кадры анимации идут в ней подряд |
| `flags` | альфа-тест, смешивание (`MATF_BLEND`), сложение (`MATF_ADD`), вода, нет текстуры, без столкновений |
| `group` | группа материала ZenGin (звук шагов) |
| `frameCount`, `frameMs` | число кадров анимации текстуры и длительность кадра |
| `opacity` | множитель альфы для смешиваемых материалов |
| `scroll` | прокрутка текстуры, 1/4096 повтора в секунду |

Таблица текстур хранит хеши записей `tex/...`. Одна текстура загружается один раз, сколько бы материалов на неё ни ссылалось.

`WorldPortal` — зона, которая переносит игрока в другой мир архива: границы, хеш индекса мира назначения, точка и направление прибытия. Если точка прибытия не нашлась при запекании, стоит флаг `PORTALF_USE_SPAWN` и игрок попадает на стартовую точку мира назначения.

`WorldLadder` — зона подъёма: границы лестницы с запасом 45 см по сторонам и 100 см сверху.

`ChunkInfo` — границы чанка, хеш его записи в архиве и размеры.

Чанк подгружается по требованию:

```
ChunkHeader (32 байта): magic, batchCount, vertexCount, indexCount, origin[3], posScale, uvScale
ChunkBatch[batchCount] (по 24 байта): material, detail, firstIndex, indexCount, bbMin[3], bbMax[3]
WorldVertex[vertexCount] (по 16 байт)
u16 indices[indexCount]
```

Партия (`ChunkBatch`) — непрерывный диапазон индексов с одним материалом и одним классом детализации. Границы партии записаны в квантованных координатах чанка; по ним рантайм отсекает партии вне кадра.

Класс детализации задаёт дальность прорисовки: 0 — всегда (меш мира и крупные объекты), 1 — средние объекты (по умолчанию до 70 м), 2 — мелкие (до 35 м). Конвертер назначает класс по размеру объекта: мелкие — с радиусом до 1,6 м, средние — до 4,5 м.

Партии в чанке отсортированы: сначала непрозрачные, затем с альфа-тестом, затем полупрозрачные; внутри — по классу детализации и материалу. Так состояние GPU меняется реже.

`WorldVertex`:

| Поле | Тип | Смысл |
|---|---|---|
| `x, y, z` | `i16` | позиция: `мир = origin + xyz · posScale` |
| `w` | `i16` | выравнивание, всегда 1 |
| `u, v` | `i16` | текстурные координаты: `uv = st · uvScale`, `uvScale = 1/1024` |
| `r, g, b` | `u8` | запечённый статический свет |
| `a` | `u8` | вес дневного света: 255 на улице, 0 под лайтмапом и в подземном мире |

Правила нарезки:

- Треугольник попадает в ячейку сетки по центру тяжести в плоскости XZ.
- Все чанки квантуют позиции на одной мировой решётке: шаг равен 0,5 см, а начало чанка кратно шагу. Вершина на границе двух чанков попадает в обоих в одну и ту же точку, поэтому на стыках нет щелей. Чанк, который не укладывается в 16 бит с шагом 0,5 см (в нём есть гигантский треугольник), удваивает шаг, пока не уложится.
- Координаты UV сдвигаются на целое число повторов, чтобы уложиться в 16 бит. Если размаха одного материала в чанке не хватает, сдвиг считается для треугольника отдельно. Треугольник шире 32 повторов обрезается, конвертер сообщает об этом.
- Вершин в чанке не больше 65535; иначе ячейка делится на части.
- Объекты мира запекаются прямо в чанки как обычные треугольники; свет они берут от земли под собой. Модели запекаются в позе покоя, декали — как прямоугольники.
- Те же вершины и индексы служат сеткой столкновений; партии с флагом «без столкновений» в неё не попадают. Поверхности воды образуют отдельную сетку, по ней определяется уровень воды.
- Передние грани обходятся против часовой стрелки на экране. Меш мира из ZenKit уже приходит в таком порядке; конвертер проверяет это по доле площади, обращённой вверх.

## Проходы отрисовки

| Проход | Что рисуется | Состояние |
|---|---|---|
| небо | купол с градиентом; в подземном мире пропускается | без глубины, без отсечения граней, без тумана |
| мир | непрозрачные партии и партии с альфа-тестом, от ближних чанков к дальним | проверка и запись глубины, отсечение задних граней |
| смешивание | вода, декали, свечение, от дальних чанков к ближним | проверка глубины без записи, обе стороны граней |

В проходе смешивания цвет равен `текстура × свет`, альфа — `альфа текстуры × opacity`. Материал с `MATF_ADD` прибавляется к кадру и в тумане гаснет до нуля, остальные смешиваются по альфе и уходят в цвет тумана.

## Сохранённое положение (`state.bin`)

48 байт: сигнатура `G3ST`, версия, хеш мира, признак полёта, положение глаз, направление взгляда, время суток, дальность прорисовки, контрольная сумма. Файл с неверной суммой, недопустимыми значениями или миром, которого нет в архиве, игнорируется.

## Система координат

Как в ZenGin: левая, Y вверх, +Z вперёд, единица — сантиметр. Матрицы хранятся по столбцам.
