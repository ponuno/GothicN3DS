# Что дальше

## Первый запуск на консоли

Код для 3DS проверен компиляцией, но не запускался. Порядок действий на первом запуске:

1. Собрать `make` в окружении devkitPro. Если сборка падает, это ошибка базы — её нужно исправить в первую очередь.
2. Запустить с `data.pak` тестовой сцены (`g3ds-bake synth`). Картинка должна совпасть с кадрами `g3ds-host`.
3. Сверить по пунктам:

| Что смотреть | Если не так |
|---|---|
| Мир виден, а не вывернут наизнанку (в `g3ds-host` он правильный) | режим отсечения граней в `gfx_c3d.cpp` (`C3D_CullFace`) |
| Текстуры не перевёрнуты и не «в клетку» | раскладка тайлов в `tools/bake/texture_bake.cpp` |
| Заборы и деревья с прозрачными вырезами | альфа-тест и порядок полубайтов альфы |
| Туман сгущается вдаль, без полос | второй этап TexEnv в `setFogStage` |
| Нет мусора при пересечении границ чанков | отложенное освобождение (`reap`) в `gfx_c3d.cpp` |

4. Записать цифры с нижнего экрана на тестовой сцене и на `WORLD.ZEN`: время кадра, доли CPU и GPU, треугольники, свободную линейную память.

## Решение по этапу 0

Критерий из плана: Старый лагерь должен давать около 20 кадров/с с запасом по памяти. Геометрия мира — только часть нагрузки, поэтому до выводов нужны ещё два замера:

- загрузка `GOTHIC.DAT` в виртуальную машину Daedalus из ZenKit на консоли (время и память);
- 30–40 скелетных моделей в кадре (появится на этапе 3).

Если геометрия мира одна занимает больше половины кадра, сначала стоит попробовать пункты из раздела «Производительность».

## Ближайшие задачи

**Мир (этап 2)**

- Лайтмапы помещений. Сейчас для всех полигонов берётся повершинный свет; конвертер сообщает, сколько треугольников используют лайтмапы.
- Воба: статические объекты мира (`world_vobs`) с их мешами `.MRM`.
- Коллизии и высота пола, чтобы камера ходила по земле.
- Небо и смена времени суток (модуляция повершинного света цветом неба).
- Вода и другие полупрозрачные материалы: отдельный проход со смешиванием.
- Порталы и секторы BSP для помещений.

**Производительность**

- Чтение и распаковка чанков в отдельном потоке на втором ядре; сейчас загрузка идёт в основном потоке, не больше двух чанков за кадр.
- `C3D_FrameEnd(GX_CMDLIST_FLUSH)` вместо сброса всей линейной памяти каждый кадр (комментарий в `frameEnd`).
- Часто используемые текстуры в VRAM (6 МБ), остальные в линейной памяти.
- Уровни детализации для дальних чанков и объединение мелких партий.
- Порядок индексов под кэш вершин.

**Данные**

- Анимированные текстуры (`NAME_A0`, `NAME_A1`, …).
- Контрольные суммы ресурсов в архиве: сейчас повреждение ловится только проверкой заголовков и индексов.
- Конвертация остальных миров (`OLDMINE.ZEN`, `FREEMINE.ZEN`, `ORCGRAVEYARD.ZEN`, `ORCTEMPEL.ZEN`) в один архив и переход между ними.
