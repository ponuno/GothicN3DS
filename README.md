# Gothic 3DS — база порта

Основа для запуска мира Gothic 1 на New Nintendo 3DS: конвертер ресурсов на ПК, формат данных под PICA200 и рантайм с потоковой подгрузкой мира. Это этапы 0–2 плана; игровой логики, персонажей и звука здесь ещё нет.

Данные игры в репозиторий не входят и не распространяются: конвертер читает вашу установленную копию.

![Тестовая сцена, отрисованная ПК-сборкой рантайма в разрешении верхнего экрана](docs/preview.png)

## Что внутри

| Часть | Каталог | Назначение |
|---|---|---|
| Конвертер `g3ds-bake` | `tools/` | Читает `WORLD.ZEN` и текстуры из VDF через ZenKit, пишет `data.pak` |
| Ядро | `core/` | Форматы архива, текстур и чанков мира; общие для ПК и консоли |
| Движок | `engine/` | Потоковая подгрузка чанков, отсечение, камера |
| Бэкенд 3DS | `platform/3ds/` | libctru + citro3d, вершинный шейдер PICA |
| Бэкенд ПК `g3ds-host` | `platform/host/` | Программный рендер 400×240 с тем же конвейером, для отладки без консоли |
| Тесты | `tests/` | Модульные и сквозные, включая импорт из форматов ZenGin |

Рантайм (`core`, `engine`, `platform`) написан на C++17 без STL, исключений и RTTI. Инструменты — C++20, этого требует ZenKit.

## Сборка на ПК

Нужны CMake 3.16+, компилятор с C++20 и git. ZenKit скачивается при настройке.

```sh
cmake -S . -B build
cmake --build build -j
ctest --test-dir build --output-on-failure
```

Проверка всей цепочки на встроенной тестовой сцене, игра не нужна:

```sh
./build/g3ds-bake synth -o data.pak
./build/g3ds-host --pak data.pak --frames 300 --shots 4 --out frame
```

`g3ds-host` пролетает камерой по миру, сохраняет кадры в PNG и печатает статистику: треугольники и вызовы отрисовки на кадр, занятую память, перерисовку.

## Запекание мира Gothic

```sh
./build/g3ds-bake world --game "/путь/к/Gothic" -o data.pak
./build/g3ds-bake info data.pak
./build/g3ds-host --pak data.pak --still --shots 1 --out world
```

Полезные параметры: `--zen OLDMINE.ZEN` (другой мир), `--chunk 4000` (размер чанка в см), `--max-tex 128` (длинная сторона текстуры), `--quality 0|1|2` (качество ETC1), `--flip` (перевернуть порядок обхода вершин).

Конвертер сам проверяет порядок обхода: в отчёте есть строка `winding check`, и если мир вывернут наизнанку, она предложит запечь его с `--flip`. Для Steam-версии Gothic 1 параметр не нужен.

## Сборка для 3DS

Нужен [devkitPro](https://devkitpro.org/wiki/Getting_Started) с группой пакетов `3ds-dev` (devkitARM, libctru, citro3d).

```sh
make
```

Получатся `gothic3ds.3dsx` и `gothic3ds.smdh`. На SD-карте:

```
/3ds/gothic3ds/gothic3ds.3dsx
/3ds/gothic3ds/gothic3ds.smdh
/3ds/gothic3ds/data.pak
```

Запуск через Homebrew Launcher. Управление:

| Кнопка | Действие |
|---|---|
| Circle Pad | движение |
| C-Stick или A/B/X/Y | обзор |
| L / R | вниз / вверх |
| ZL, ZR или крестовина вверх | быстро |
| Крестовина влево / вправо | дальность прорисовки |
| START | выход |

На нижнем экране — время кадра, загрузка CPU и GPU, треугольники, чанки и память. Это и есть замер для проверки осуществимости.

Шейдер лежит уже собранным (`platform/3ds/world_shbin.h`). После правки `world.v.pica` его нужно пересобрать, команды — в `scripts/shbin2h.py`.

## Что проверено, а что нет

Проверено в этой сборке:

- ПК-часть собирается без предупреждений, все тесты проходят, в том числе под AddressSanitizer и UBSan.
- Импорт из форматов ZenGin: тест сам записывает через ZenKit мир `.ZEN` с BSP-деревом и стартовой точкой внутри `.VDF` и текстуры DXT1/DXT3, затем читает их обратно.
- Раскладка текстур ETC1 и ETC1A4 совпадает тексель в тексель с выборкой эмулятора Azahar (его декодер, все мип-уровни).
- Шейдер собирается ассемблером picasso.
- Код для 3DS компилируется под ARMv6K (clang) с настоящими заголовками libctru и citro3d без предупреждений; все внешние символы есть в этих библиотеках.
- `Makefile` выдаёт правильные команды компиляции, линковки и упаковки на правилах devkitARM (сухой прогон).
- Настоящий `WORLD.ZEN` из Steam-версии Gothic 1: 106 722 треугольника и 325 текстур запекаются без ошибок, вид из стартовой точки в `g3ds-host` правильный.

Не проверено:

- **Сборка `.3dsx` настоящим devkitARM и запуск на консоли или в эмуляторе.** В среде, где писался код, devkitPro недоступен.
- Освещение помещений (лайтмапы) и воба на настоящем `WORLD.ZEN`: они пока не импортируются.
- Файл `.github/workflows/build.yml` не запускался.

Первые шаги на железе описаны в [docs/ROADMAP.md](docs/ROADMAP.md), форматы данных — в [docs/FORMATS.md](docs/FORMATS.md).
