# План оптимизации (сводка на fix49, 13.10.2026)

Цель: город Archolos на New 3DS стабильно 60 fps (Gothic 1 уже держит 60 даже на максимуме).
Что известно о стоимости кадра: GPU ≈ 5 мс + 0,22–0,27 мс на 1000 треугольников; упора в fill-rate нет;
пейсер (детали 35 %, дистанция 50 %) в тяжёлых сценах Archolos выбирает пределы; крупные объекты (15–19 тыс. треугольников) уменьшаются только пеканием.

## 1. Сделано (проверено пользователем или тестами)
| Что | Версия | Эффект |
|---|---|---|
| Ярусы чанков, кластеры, запечённая видимость, дальний слой, LOD-заглушки | fix18–33 | меньше треугольников и draw call'ов |
| Склейка draw call'ов, быстрый вершинный шейдер статики | fix31, fix36 | меньше CPU на кадр |
| Нижняя граница дистанции пейсера 50 % | fix33 | чуть больше запаса |
| `--simplify` (мир и персонажи) | fix37 | пользователь: «картинка стала плавнее», особенно на минимуме |
| Куча: linear 48 МБ, бюджет чанков 44 МБ | fix41 | кэш чанков больше, меньше отказов |
| Частота экрана по кадру 45–80 Гц, журнал просадок, плавное появление жителей | fix43 | 80 Гц на панели работает |
| Снят потолок 60 при экране выше 60 Гц, сброс пейсера при смене режима | fix45 | динамический FPS выше 60 |
| «Ровно 40» (экран 40 Гц, 25 мс на кадр) | fix46 | новый лок |
| Листва и деревья не пропадают (ветровой проход использовал чужую классификацию) | fix44 | пользователь проверяет |
| «Держать 72/80» (деталь по времени кадра выбранной частоты) | fix48 | ждёт проверки |
| Доворот кадра по повороту камеры (пункт 1 кандидатов): при обновлении экрана без нового кадра показывается старый, сдвинутый по yaw (адрес буфера, без GPU) | fix49 | опыт, выкл. по умолчанию; только ПК-тест математики, на консоли не проверялось |

Нижний экран: панель перерисовывается только при изменении (`panel.draw(..., !panelShown)`), отчёт — по одной строке за кадр, только если включён. Отдельной экономии там нет.

## 3. Кандидаты (по ожидаемой пользе)
1. ~~**Репроекция камеры (только поворот).**~~ Сделано в fix49 для yaw (см. таблицу «Сделано»). Осталось: pitch (сдвиг внутри столбца на 3 байта — нужно узнать требования дисплея к выравниванию), параллакс от смещения камеры не исправляется.
2. ~~**Кэш подгрузки чанков и жителей (SD → линейная память, фоном по ходу).**~~ Сделано в fix50 (чтение наперёд, `engine/readahead.*`); ждёт проверки на консоли. Исходно: Бьёт в главную жалобу: резкая подгрузка NPC и чанков при движении. Продолжение fix43 (`prefetchRange`, `startsPerFrame`).
3. ~~**Адаптивное разрешение**~~ Не делаем (разбор в fix51): по замеру fix35 вдвое меньше пикселей даёт ~6 % gpu (2 мс из 35,6), т. е. 320×240 вместо 400×240 — ≈0,2 мс на кадр; а GX display transfer умеет только уменьшать (2:1), растяжение потребовало бы второго GPU-прохода (цель-текстура + квад) в и без того сложном конвейере кадров. Вернуться, только если опыт покажет fill-bound (сравнить gpu с «Сглаживанием» 2×2: у него в 4 раза больше пикселей).
4. ~~**Усиление `--simplify-ratio`** для классов A (крупные объекты).~~ Сделано в fix51: `--simplify-ratio-large R` / `--simplify-error-large CM` (второй, более жёсткий проход по крупным объектам); нужен ребейк, ждёт проверки на консоли.
5. ~~**Ускорение дистанционной ступени пейсера**~~ Сделано в fix52: дальность возвращается шагом раз в 40 кадров (0,7 с, было 120), а при нагрузке > 135 % сокращается сразу вместе с объектами; ждёт проверки на консоли.
6. ~~**Стерео-3D по буферу глубины**~~ Не делаем: игра включает `gfxSet3D(false)` (main.cpp), ползунок не используется; нужно было бы второе изображение на GPU/через глубину без возможности проверить здесь. Возвращаться только если появится спрос. Исходно: **Стерео-3D по буферу глубины** (второй глаз репроекцией, стоимость почти моно). Нужно только если 3D-ползунок используется.
7. **Таймер частоты экрана по сцене**: в диалогах и меню 40–48 Гц (батарея).
8. ~~**ETC1-текстуры**~~ уже есть (`GPU_ETC1`/`GPU_ETC1A4` в `gfx_c3d.cpp`, запекание ETC1 в пекаре); сейчас `--max-tex 128`.

## 4. Отклонено или отложено
- Настоящая генерация кадров (оптический поток): нет ни памяти, ни GPU.
- Разгон ядра, патчи прошивки / кастомная прошивка: нужен CFW, риск; память под приложение даёт только изменение раскладки системы.
- 100 Гц как игровой режим: рябь и риск для панели.
- Нижний экран 30 Гц: на производительность не влияет.
- Сглаживание 2×2 (fix38–42): работает только при старте, разницы пользователь не увидел → по умолчанию выключено.

## 5. Память (справка)
Область приложения New 3DS ≈ 124 МБ; linear 48 МБ (libctru по умолчанию 32); обычная куча ≈ 75 МБ (`u` ≈ 46 МБ занято). Отдать куче скриптов Archolos часть linear-памяти имеет смысл только если скрипты упираются в кучу (по HUD: `heap`/`u`).
